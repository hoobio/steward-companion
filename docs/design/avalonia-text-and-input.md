# Avalonia text, input and tests

The Avalonia build uses only the fonts bundled in `src/Steward.Desktop/Assets/Fonts` (`AvaloniaResource`, loaded as `avares://Steward.Desktop/Assets/Fonts#<family>`), on every OS, Windows included, with no system font in any family list: the Segoe UI and Segoe Fluent Icons licence forbids shipping them, and Wine has neither. Text follows hoobi-design's typography: `ContentControlThemeFontFamily` and `DisplayFontFamily` are Hanken Grotesk in three static TTFs, Regular, SemiBold and Bold, the weights the views use: Avalonia 12.1.3 does not map `FontWeight` onto a variable font's `wght` axis (the variable `HankenGrotesk[wght].ttf` rendered Light to Bold at one width, with Bold as a synthetic `FontSimulations.Bold`), so another weight is another static file from the same commit. Text widths and glyph shapes therefore differ from the WinUI baseline by design; parity still compares layout, metrics, colour, corner radius, spacing and text vertical position, and a layout that breaks because Hanken Grotesk runs wider or narrower than Segoe UI is listed, not silently resized. `MonoFontFamily` is Cascadia Mono, since hoobi-design's Dank Mono is a commercial font with no licence for redistribution in `D:\hoobi-design`. `IconFontFamily` is Fluent UI System Icons (Resizable, the 20px regular and filled set in one file). FluentAvalonia's own control glyphs come from the symbol font embedded in `FluentAvalonia.dll`. Each licence text sits beside the fonts and is copied to the output as `Assets\Fonts\*.txt`. Text vertical metrics are calibrated from the font metrics (`Styles/SegoeMetrics.cs`, computed from each element's own `FontSize`) by global styles in `Controls.axaml`: `:is(TextBlock)` covers every Hanken Grotesk and icon-font `TextBlock` and its subclasses, so `AccessText` (the label of a `Button`, `CheckBox`, `RadioButton` or `MenuItem` with string content) and `SelectableTextBlock` too; a `TextBox` takes the `LineHeight`, which its template passes to its `TextPresenter`, and the `TextPresenter` takes the `RenderTransform`, so the caret and the selection move with the glyphs. WinUI lays Segoe UI out on its win metrics (ascent 2210, descent 514 of 2048, a line of 1.3301 em) where Hanken Grotesk's are 1.000 and 0.303 em. A Hanken line takes `LineHeight` 1.3301 em, Segoe's line box, so row heights stay on WinUI's. The baseline follows WinUI's device-pixel rule, measured on the baseline captures at 100% and 150% (dialog titles, button labels, Settings cards): Segoe's ascent and descent are each rounded to device pixels, centred in the line box rounded up to device pixels, and the baseline snaps half up (13px at 100% sits 15px below the line top, 21 device pixels at 150%; 20px sits 22, and 32 at 150%). Hanken's capitals (0.697 em) and Segoe's (0.700) then cover the same rows, but hinted Segoe inks one row higher at the top on the same baseline, so WinUI's own pills read 7px above and 6px below their capitals where Hanken on that baseline reads 8 and 6. Text in a box (anything not stacked) therefore centres its capitals on the line box and snaps to a device pixel, at most one device pixel above WinUI's baseline (`SegoeMetrics.BaselineShift`, `free: false`), which keeps the ink gaps equal within 1px and every line within 1px of WinUI; text stacked with others in a vertical `StackPanel`, directly or through a `Grid` or a `ContentPresenter` (a page subtitle, a settings section heading, a Settings card's title and description, an addon's name and folder lines), or marked `SegoeMetrics.IsFree` (the install picker's label, which centres in the picker's 30px row rather than in a box of its own), keeps WinUI's baseline. `SegoeMetrics.IsEnabled`, set by the global styles on every `TextBlock` and `TextPresenter`, computes the `RenderTransform` from the font size, the family and the `TopLevel`'s render scaling, and recomputes it when the scaling changes (a window moved to another monitor). The family is the typeface the text renders with, so FluentAvalonia's `ContentDialog` title, whose template names the family `Default`, is calibrated as Hanken; it was 2px high at 100% while it was not. Avalonia rounds a measured size up to whole device pixels (`LayoutHelper.RoundLayoutSizeUp`), as WinUI does for a `TextBlock` (13px measures 18 at 100% and 26 device pixels at 150% in both), and an arranged position to the nearest device pixel with .5 to even (`LayoutHelper.RoundLayoutValue`, `Math.Round`), where WinUI rounds .5 up; `LayoutHelper` is static, so a half-pixel centring can land 1 device pixel above WinUI's (the dialog command row's labels) and at 150% the Settings card groups drift by up to 2 device pixels. The shared control styles keep the paddings the boxed rule centres: `ButtonPadding` 13,4,13,4 (WinUI 13,4,13,5), `ComboBox` 12,6,0,6 with the selection and placeholder centred (12,5,0,7), `ComboBoxItem` 11,7,11,6 at 14px, the size WinUI's popup items take since its popup does not inherit the box's 13px (WinUI 11,5,11,7, items 32px apart plus the 2px template margins, as measured), `ToolTip` 9,7,9,7 (9,6,9,8), `CheckBox` and `RadioButton` 8,7,8,0 with `VerticalContentAlignment` `Top` (FluentAvalonia 3.1.0's label presenter read `Top` on Windows and `Center` on Linux, which put the label 3px low there), so the label centres on the 20px glyph; a `ToggleSwitch` with no `Content` hides FluentAvalonia's empty header and its 4px margin, so the 20px track sits on the control's centre and an On/Off label beside it centres on the track; an open `FAInfoBar` puts its title and message 15px down (WinUI 14px), so they centre on the 16px icon; a `TextBox` centres its text (`VerticalContentAlignment` `Center`), with the placeholder on the same row as typed text. A `Button.accent` (FluentAvalonia's class for a dialog's default button) is SemiBold, as WinUI's `AccentButtonStyle` is. An icon `TextBlock` takes `LineHeight` 1 em, Segoe Fluent Icons' line box (ascent 1 em, no descent), where Fluent System Icons' line gap made it 1.09 em, which made icon-bearing rows taller. Cascadia Mono is the font WinUI uses and is left alone. Fluent System Icons' 20px set inks 0.8 em (16 of its 20 units; the globe `E99B` outline is 800 of 1000 units square) where Segoe Fluent Icons inks the full em (globe `E774` 1000 of 1000), so the icon calibration scales every glyph by 5/4 about its centre (`InkScale`); at the earlier 10/9 a 20px Settings card icon inked 18px against the baseline's 20px, and at 5/4 its ink spread matches the baseline's (globe second moment 5.57/5.52px against 5.50/5.57px). `Styles/AppFonts.UseStewardFonts` (called by `Program` and the test session) registers the bundled fonts as `fonts:Steward` and makes Hanken Grotesk Avalonia's `DefaultFamilyName`, so text whose template names no family (a `FAContentDialog` string title) never falls back to a system font, and lists Segoe UI Emoji, Apple Color Emoji and Noto Color Emoji as `FontFallbacks` for emoji, which no bundled font carries; no emoji font is bundled. Text renders with grayscale antialiasing (`TextRenderingMode.Antialias` on every `TopLevel` and its visual ancestors, since the drawn caption buttons sit beside the window under its host), as WinUI's does, rather than Skia's subpixel default.

Text centring is tested in `tests/Steward.Desktop.Tests`. `TextCentringTests` renders each text-bearing control type the app uses (`TextBox` typed and placeholder at each real size, `Button`, accent `Button`, `ToggleButton`, `HyperlinkButton`, `ComboBox`, `ComboBoxItem`, the segmented `ListBoxItem`, `CheckBox`, `RadioButton`, `ToggleSwitch`, `MenuItem`, `ToolTip`, `FAInfoBar`, and a `TextBlock` and a `SelectableTextBlock` in a 32px box) with `HXE`, and asserts that the ink gap above equals the gap below within 1px, that a placeholder sits on typed text's row, that the caret and the selection span the text, and that accent buttons render SemiBold; it reports `weakauras gjpqy` too. `TextCentring.Verify`, called by every page and dialog render test, swaps every visible single-line text in the frame for `HXE`, takes its box (the nearest `Button`, `ListBoxItem`, `ComboBox`, `MenuItem`, `TextBox`, `ToolTip` or `FAInfoBar`, a template `LayoutRoot`, or the nearest filled ancestor; a check box's or radio button's glyph, a toggle switch's track, also for a label in the same panel as the switch, an InfoBar title's icon) and asserts the same gaps, so a new control or view is checked with no new test. It skips text stacked with another line in its box, a box taller than three lines, a box clipped by a scroller, and InfoBar text wrapped below its icon, since WinUI does not centre those either. Text box carets are hidden while it measures, since a focused box's caret blinks into the ink rows. `STEWARD_TEXT_CENTRING_PNG_DIR` writes every finding to `walk.txt` and the control samples to `gaps.txt` and PNGs.

Mouse-wheel scrolling is smoothed by `Styles/SmoothScroll.cs`, which the global `ScrollViewer` style switches on: each notch scrolls the system's `SPI_GETWHEELSCROLLLINES` lines of 16px (48px at the default 3, a page when the setting is "one screen", and 3 lines off Windows; Wine answers the system call itself) and eases out over 250ms (cubic), a notch during the animation adds to the pending target, a fractional delta (a precision touchpad) scrolls at once without animation, and the target is clamped to the live extent every frame. The handler runs on the tunnel route, so an outer viewer leaves a notch to the innermost viewer that can still move that way, and a viewer at its end lets the notch chain outward; any offset change it did not write (keyboard, the scroll bar, bring-into-view) ends the animation. DirectManipulation's own curve is not published, so the 250ms ease-out is a choice, and the 16px line is taken from WinUI's per-notch distance of about 48px at 3 lines, which was not measured here.

A middle-button press starts autoscroll (`Styles/AutoScroll.cs`, ported from earmark), which the global `ScrollViewer` style switches on for every viewer. The press goes to the innermost enabled viewer under the pointer that can scroll vertically, so a list inside a page or dialog scrolls itself, and a viewer with no room (a `TextBox` template's) passes the press outward. A 24px marker shows at the press point in the adorner layer, and the cursor changes to the north-south arrow. The speed follows Firefox's curve: no movement within 12px of the press point, then pixels per 20ms of the distance in 12px units to the power 1.5, less one (`AutoScroll.Speed`, `AutoScroll.Step`). A press held and dragged past 12px ends on release; a click without a drag stays on until the next press. Any press, a wheel notch, Escape, deactivation of the window or removal of the viewer ends it. Each frame sets `Offset`, which ends a running `SmoothScroll` animation. The marker fades in over `Services/Motion.Duration` (150ms, or none when Windows animation effects are off; off Windows animation is always on).

A `ScrollViewer`'s scroll bars take pointer input over a 22px band from the edge, while they draw the same pixels as FluentAvalonia 3.1.0's 14px bar (`Styles/ScrollBarHitArea.axaml`, included after `Controls.axaml`). FluentAvalonia scales the collapsed `Thumb` to 0.35 of its width with a `RenderTransform`, which also shrank its hit area to about 3px, so a quick press and drag on the thin bar paged instead of dragging. The bar is 8px wider with a -8px near-side margin, so the `Auto` grid column and row stay at 14px and the other bar does not move. The track rectangle and the line buttons keep their place through an 8px margin. The `Thumb` fills the whole band and draws its 8px `ThumbVisual` at the earlier position, and the collapse transform is on `ThumbVisual`, not on the `Thumb`. Avalonia hit-tests a child only inside its parent's bounds, so the bar itself must be wide. The 8px offset is a whole number of device pixels at 100%, 125%, 150% and 175%, so layout rounding puts every part on the same device pixel; `ScrollBarHitAreaTests` renders with and without the file at 100%, 125% and 150%, collapsed and expanded, and finds no channel more than 1 level apart. At 175% the collapsed thumb edge differs by a few percent of antialiasing coverage, and the horizontal bar's right arrow sits 1 device pixel lower. The wider band takes clicks from content within 22px of a scrollable edge: the Get addons dialog's Install buttons lose their right 10px while the results list can scroll.

Every glyph in the Avalonia views goes through `Styles/Glyphs.axaml` (`Glyph.<Name>` keys, named after the Segoe Fluent Icons glyph the WinUI build used) and `IconFontFamily`, and `BindConvert.Glyph` reads the same keys. Each key maps to the `ic_fluent_<name>_20_regular` code point in `fonts/FluentSystemIcons-Resizable.json` of the same commit (WinUI Segoe code point, then the Fluent icon): ChevronDown `E70D` `E488` chevron_down, ChevronUp `E70E` `E490` chevron_up, Edit `E70F` `E837` edit, Add `E710` `E00D` add, More `E712` `EC72` more_horizontal, Setting `E713` `F00F` settings, Search `E721` `EFD7` search, Refresh `E72C` `E0BF` arrow_clockwise, Lock `E72E` `EBAC` lock_closed, CheckMark `E73E` `E460` checkmark, Oem `E74C` `E685` desktop, ChevronRight `E76C` `E48E` chevron_right, Globe `E774` `E99B` globe, UpdateRestore `E777` `E175` arrow_sync_circle, Error `E783` `E877` error_circle, Warning `E7BA` `F561` warning, Page `E7C3` `E6E9` document, TaskView `E7C4` `F5E5` window_multiple, PowerButton `E7E8` `EEBD` power, Game `E7FC` `E967` games, FolderOpen `E838` `E90B` folder_open, Sync `E895` `E171` arrow_sync, Download `E896` `E0DD` arrow_download, Document `E8A5` `E7BB` document_text, OpenInNewWindow `E8A7` `ECF4` open, Folder `E8B7` `E8EB` folder, Library `E8F1` `EB38` library, BulletedList `E8FD` `F318` text_bullet_list_ltr, Code `E943` `E54E` code, Info `E946` `EA88` info, Diagnostic `E9D9` `EEF7` pulse, ErrorBadge `EA39` `E6D5` dismiss_circle. Oem, UpdateRestore, TaskView and Diagnostic have no same-design Fluent icon and use the nearest one. A new glyph is a new key here with its Fluent code point, never a literal code point in a view.

`tests/Steward.Desktop.Tests` renders off-screen through `Avalonia.Headless` with Skia (`UseHeadlessDrawing` off), driving one `HeadlessUnitTestSession` per assembly from an xunit.v3 assembly fixture (`Avalonia.Headless.XUnit` needs xunit.v3 3.2.2), with parallelisation off, since every test runs on the one UI thread and a test pumping the dispatcher would otherwise run another test inside its own wait. Each test that touches `MainViewModel` or a page builds its own host (`AvaloniaSession.NewHost`, `App.BuildHost` over a fresh data folder) and disposes it, which also closes the log file, since `FileLoggerProvider` is a factory registration the container owns. `NewHost` passes `App.BuildHost` an `OfflineHandler` as the primary handler of the `Steward` and `Addon` named clients, and `AvaloniaSession` gives `ManifestIcon.Http` the same, so no test opens a socket; every request attempted is queued on `AvaloniaSession.Requests` and fails with `HttpRequestException`. The data folder (state, logs, `guides`, `icons`) comes from `AppDataFolder`, registered by `AddStewardServices` from the `dataFolder` argument, and `ManifestIcon.CacheFolder` is set from it, so a test touches nothing under `%LocalAppData%`. A test closes a dialog with `AvaloniaSession.CloseDialog`, which waits for `ShowAsync` to return: FluentAvalonia completes it 200ms after `Hide()`, and `AppDialogs` queues the next dialog behind it. A test hides `MainWindow` rather than closing it, since its close path shows the close-to-tray confirmation through `AppDialogs`. It checks that the shell constructs on the Addons page, every page resolves as a singleton, every dialog constructs, a URI image draws once its stubbed download decodes, a 404, an HTML 200 and undecodable bytes each raise `IconImage.Failed`, product icons load from the bundled assets, a dialog shown through `AppDialogs` is 440 wide with 8px corners, the `#2B3140` fill and the accent primary button, every font resource loads its bundled font, every `Glyph.` key is in the icon font, each text weight loads its own face with no simulation, text and icons take the Segoe line boxes through the global style, the wheel animation's notch size, easing, accumulation, clamping and chaining hold on an injected clock, a second click on the install picker and the account button closes its flyout, no hover or press fade passes through a lighter colour, the progress ring follows WinUI's frames and draws an accent arc only while active, the acrylic tint is `#9313161D`, saturation follows the CSS matrix, a flyout over a white block shows that block blurred under the tint and the page ground beside it within 2 levels of the composite, an open ComboBox list does the same over the page and over a dialog in the overlay layer, and an overlay presenter or a `Border` turns to the solid `#181B23` while its window is inactive (`AcrylicTests`, `STEWARD_ACRYLIC_PNG` saves the frame, and the ComboBox frame beside it as `combo-<name>`), the Get addons loading ring is visible and active while the view model loads, and the shell renders a 1280x820 frame; setting `STEWARD_SHELL_PNG` to a path also saves that frame there. The Desktop Preview `ui-tests` job runs it and the Core suite on `macos-latest` (arm64), `macos-26-intel` (x64), `windows-latest` (`net10.0` and the Windows TFM) and `ubuntu-latest` (under `xvfb-run`) with every render variable set (`STEWARD_TEXT_CENTRING_PNG_DIR`, `STEWARD_ACRYLIC_PNG`, `STEWARD_SHELL_PNG`, `STEWARD_HOME_PNG_DIR`, `STEWARD_SETTINGS_PNG_DIR`, `STEWARD_SYNC_PNG_DIR`, `STEWARD_GUIDES_PNG`, `STEWARD_DIALOGS_A_DIR`, `STEWARD_DIALOGS_B_PNG_DIR`, `STEWARD_BANDING_PNG_DIR`), so every page, dialog, flyout and state renders through that OS's Skia with the bundled fonts and the text-centring walk runs there; it uploads the PNGs and the xunit TRX results as `ui-tests-<os>-<arch>` and gates `pre-release`.

The UI path suite in `tests/Steward.Desktop.Tests/UiPaths` drives the real shell through the Linux ledger's numbered paths (`UiPathLedger`, one entry per path, each driven or skipped with its reason; `UiPathLedgerTests` fails when an id is missing). Each area test builds a `UiPathWorld`: a temp WoW tree (root `.build.info`, `_classic_beta_` and `_forever_` with `.flavor.info`, AddOns TOCs and a `Steward.lua`), a seeded `state.json` (`auto_update` never, guild 1, the beta selected, install records), and `FakeApi`, a primary handler that answers `/api/me`, banners, manifests, CurseForge discover, search, match and files, the admin and member roster and the character push, and records every other request as unrouted; any host other than `api.hoobi.io` and `addon.test` throws. It signs in by setting `IsSignedIn` and calling the private `LoadAsync`, so no session token or keyring is read. Three internal seams keep it off the machine: `MainViewModel.DiscoverWowInstalls` (the temp installs instead of the registry, drives and Wine roots), `MainViewModel.ScansStore` (no Store scan from a test on Windows) and `ShellOpen.Launch` (folders and links are recorded, not opened); every area asserts that each install sits under the temp root. Input is headless `MouseMove`, `MouseDown`, `MouseUp`, `MouseWheel`, `KeyPress`, `KeyRelease` and `KeyTextInput` on the `TopLevel` that holds the target, popups included. `Dispatcher.UIThread.RunJobs` does not fire dispatcher timers, so `UiPathWorld.WaitFor` pushes a dispatcher frame per poll, and a hover sets a zero `ToolTip.ShowDelay` on the target. `STEWARD_UIPATHS_PNG_DIR` saves one PNG per step, the window with each open popup drawn over it, and `results.txt` with each path's pass, fail or skip and its time; the `ui-tests` job sets it and uploads `uipaths-<os>`. Paths outside the client area (caption buttons, title bar drag, resize), the OS tray and its menu, native X11 popups under a compositor, OS default-app associations, the OS folder chooser, second launches and process exit are in the skip table; the Start on login card is enabled only in a GitHub release build, so paths 59 and 60 are skipped too.

`src/Steward.Desktop/Assets/Steward.ico` (16 through 256px, PNG-compressed frames) is the one source of the app's icon: it is the `ApplicationIcon`, the `Window.Icon` on `MainWindow` and the tray icon, and the csproj sets `AssemblyTitle` to "Steward" so the exe's `FileDescription`, which the taskbar jump list shows, reads "Steward" instead of the assembly name `Steward.Desktop`.
