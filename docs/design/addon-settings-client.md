# Addon settings in the app

`docs/design/addon-settings.md` is the contract and the source of truth. The app has no settings editor: addon settings, talent plans and action bar plans are edited on guild.hoobi.io, and the app moves them between the game's SavedVariables files and the website through the URL fragment, never through a server. `AddonSettingsPayload` (Core, `AddonSettingsTransfer.cs`) is the codec (UTF-8 JSON, raw DEFLATE, base64url with a `v1.` prefix), reads a `steward://import#v1.<payload>` link or the bare payload (URL-encoded or not, at most 64 KB) and builds `https://guild.hoobi.io/addon-settings[?view=talents|actionbars]#v1.<payload>`, refused over 32,000 characters. `SettingsAccount` resolves one WoW account's files: a row's file comes from `path[0]` through `AddonSettings.SavedVariableOwners` (the `## SavedVariables` lines of each installed addon's top-level TOC), never from the schema's folder, and it holds the characters (beta-realm filter on `wowf`) and the realm-id pairing. `AddonSettingsExport.Build` writes the export (only keys present in the file; `values[folder].account|character|characterFile|class`, the class scope as `class[CLASS]["{class}"]`; `unrecorded` from `AddonSettings.UnrecordedCharacters`, the folders under a known realm with no `chars` entry, only when there are any); `SettingsPlans` reads and writes `HoobiScriptsDB.talentPlans[CLASS][group]`, `HoobiScriptsDB.spellPlans[CLASS]` (spell name to cap, a 0 cap read and written as absent) and `HoobiScripts_ActionBarsDB.plans[CLASS]`/`.account` in both positional and `[n] =` forms. A plan change in the confirmation lists what it writes (`SettingsImportItem.Details`: points added or removed per talent node, one line per changed slot by bar and button and per macro, one line per changed spell), at most 20 lines and then "and N more", under one heading per addon. A change whose new value the file already holds is `SettingsImportStatus.Unchanged`: never written or counted, and listed on one "Already the same in the game" line at the end. `AddonSettingsImport.Preview` checks every change against the local schema and the plan rules and lists each as ready, refused (with the reason) or changed in game (the file no longer holds `from`); a `class` row's change names a character, whose class picks the key; `Apply` writes each file once with `AddonSettings.Write` (never creates a file, refuses while the client runs), adds absent `keepDefault` rows, creates a new character's folder and never touches `chars`, `stanceNames`, `classEnabled` or the generated macros. Saved-variable files are read and written as Latin1 (`AddonSettings.ToFile`/`FromFile`). `AddonUpdater.GetSettingsSchemaAsync` fetches `{manifest_base_url}settings-schema/{version}.json`; a schema must pass `SettingsSchema.Refusal` or is exported as unavailable. `AddonSettingsViewModel` (Presentation) holds the Settings page's "Addon settings and plans" group (account picker, Edit on the website, Plan talents, Plan action bars, Paste from website, shown while `MainViewModel.AddonSettingsVisibility`), and `MainViewModel.ReceiveLinkAsync` sends a `steward:` link to it and anything else to the CurseForge receiver; `MainWindow.ShowSettingsImportAsync` is the confirmation dialog over a `SettingsImportSession`. A payload with no `account` is unbound: the session lists the Forever installs that have HoobiScripts and that install's accounts, defaults to the selected install and its first account, and recomputes the preview on each change; settings and new characters in it are one refused line, and its plan changes skip the conflict check. Every `steward:` link brings the window out of the tray or minimised state (`AddonSettingsViewModel.BringToFront`, `MainWindow.ShowFromTray`), so `ForegroundGate` never holds its dialog back, and it waits only for install discovery (`MainViewModel.InstallsKnown`), which a restored session runs before the startup network checks, never for the rest of the startup pass. After Apply a local banner reads "Imported N changes to <account> on <install>" with Export again, and a refusal or failure is a warning or error local banner (`ShowLocalInfoBanner`'s `level`). A link that arrives while an import or an export is in progress waits in a queue of at most 4 and is shown after it, and the busy state is cleared in a `finally` whatever the outcome. The `SettingsCard` styles are `Styles/SettingsCards.axaml`. The fixtures are `tests/Fixtures` (`HoobiScripts.lua`, a hand-written schema, the real schemas in `settings-schemas`, `addon-settings-export-vector.txt`/`.json`, which the website decodes, the website's `addon-settings-import-vector.txt`/`.json`, and `addon-settings-unbound-vector.txt`/`.json`, encoded by the app until the website's own vector replaces it); `UiPaths/AddonSettingsPaths` drives paths X7 and X8.
